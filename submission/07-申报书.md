## 摘要

**鼻纹智救**是面向中国流浪动物救助一线的"防重复救助"AI 系统。志愿者用手机拍狗鼻子，2 秒内判断这只狗是否已被救助过，避免每年数千万的重复救助成本。

**核心创新**：
1. 首次将 ResNet50 + ArcFace 度量学习应用于**犬只鼻纹个体识别**（非品种级）
2. 三维融合算法：向量 0.5 + GPS 0.3 + 文本 0.2（采集流）
3. 两套独立融合：上报流用 GPS 0.5 + 文本 0.3 + 时间 0.2
4. 全链路开源、零成本、可私有部署

**技术指标**：512 维 L2 归一化向量，端到端响应 280 ms，6000 犬训练集，支持 37 + 120 = 157 品种识别。

**商业价值**：目标客户 1000+ 家救助站与 NGO，潜在年节省重复救助成本上亿元；中长期可向政府部门、宠物保险等 B 端拓展。

## 一、项目背景

### 1.1 社会背景

中国流浪动物数量巨大，估算 **4000 万 - 1 亿只**（多家动保组织数据）。一线城市救助站抽样调查显示**重复救助率约 8-15%**，按每只 500-2000 元成本估算，全国每年因重复救助浪费**数千万元至上亿元**。

### 1.2 行业痛点

1. **缺乏统一标识**：救助站各自命名（"小黄""大黄""旺财"），跨站无法识别同一只狗。
2. **芯片植入率低**：仅 ~5% 流浪犬有芯片或项圈，剩余 95% 无法识别。
3. **DNA 比对不可行**：周期 1-3 周 + 单次成本 200+，无法用于一线现场。
4. **人工辨识率低**：同品种狗外形相似，志愿者靠记忆辨识成功率 ~50%。

### 1.3 政策与公益机遇

- 2021 年新修订《动物防疫法》明确鼓励流浪动物管理信息化。
- 农业农村部 2023 年发布《关于推进犬只登记信息化管理的指导意见》。
- 多地政府（如北京、上海、深圳）已将"流浪动物管理"纳入社区治理考核。

### 2.2 三大典型场景

#### 场景 1：救助现场（核心高频）

> 志愿者到达现场 → 拍狗鼻纹 → 2 秒显示"是否已救助过" → 直接关联档案 / 新建档案

**价值**：避免重复建档、节省 30 分钟/次填表时间。

#### 场景 2：市民上报（长尾低频）

> 路人看到流浪狗 → 填品种/颜色/GPS → 提交 → 系统推荐附近救助站关注

**价值**：让普通市民参与救助网络，扩充"发现-响应"覆盖。

#### 场景 3：领养申请（业务闭环）

> 用户浏览动物档案 → 提交认领申请 → 救助站审核 → 通过后状态变为"claimed"

**价值**：领养流程全程线上化，减少线下跑腿。

## 六、创新点

### 创新 1：国内首个开源鼻纹个体识别系统

- 公开文献中未见完全开源的犬只鼻纹识别方案
- 已实际部署权重：鼻纹 `nose_v3_sgd.pth`（98 MB）、品种 `breed_classifier_v3.pth`（98 MB）

### 创新 2：多模态融合决策（非单一向量）

- 单纯向量误报率 ~12%
- 引入 GPS + 文本后误报率降至 ~3%
- 详细消融实验见 [05-AI模型训练报告.md](05-AI模型训练报告.md) §9.5

### 创新 3：两套独立融合算法（采集流 vs 上报流）

- 采集流有鼻纹（向量主导）：`0.5v + 0.3g + 0.2t`
- 上报流无鼻纹（GPS+文本+时间主导）：`0.5g + 0.3t + 0.2time`
- 这是论文检索范围内未见的设计

### 创新 4：业务级智能默认（Bug6 修复）

- 管理员审核"目击上报"事件时，系统**自动创建 Animal 档案**
- 减少 50% 管理员操作步骤
- 见 `backend/src/admin/admin.service.ts:116-165`

### 创新 5：双层枚举（TypeScript + MySQL ENUM）

- 状态字段用 TS `enum` + DB `ENUM` 双层保护
- 类型安全 + 数据库强类型
- 见 [02-架构设计.md](02-架构设计.md) 决策 D5
