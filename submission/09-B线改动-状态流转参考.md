## 0. TL;DR — 一句话总览

**B 线把"采集 / 发现 / 又看到"三个动作,统一成"上报一次事件(intent + 数据)"**,由后端根据 `intent` 决定:
- `lost` / `found` → **自动建档**(Animal 表插入新行,event.animal_id 直接关联)
- `stray_sighting` / `profile_build` / `unknown` → 仅写事件,animal_id = NULL,等 admin 决策
- Animal.status 不再隐式默认 `LOST`,**完全由 intent 驱动**

**带来的能力**:
- ✅ 无鼻纹也能报失/捡到(场景 A / C)
- ✅ 任何动物详情页能追加"又看到"事件(场景 D)
- ✅ admin 审核端动作闭合(reject / confirm / merge / create_new 4 选 1)
- ✅ 动物时间轴(自动汇总该 animal 所有事件,不增表)
- ✅ 用户自助关联事件到动物

## 1. 状态流转核心规则(intent → status 映射)

### 1.1 Animal.status 取值(枚举不变)

| status | 含义 | 徽章色 | 谁触发 |
|--------|------|--------|--------|
| `lost` | 走失中 | 红 | 主人报失 |
| `found` | 发现中 | 绿 | 捡到者标记 / 路人 stray_sighting 经 admin create_new |
| `claimed` | 待认领 | 橙 | 走失主人申请认领 + admin 审核通过 |
| `archived` | 已归档 | 灰 | admin 主动归档 |

### 1.2 intent → status 派生规则(2026-07-06 起生效)

| intent | 来源 | AnimalsService.create 行为 | EventsService.create 行为 |
|--------|------|---------------------------|---------------------------|
| `lost` | 主人报失 | `Animal.status = LOST` | `animal_id` 缺失时自动建档,事件关联新 animal |
| `found` | 主人/发现者捡到 | `Animal.status = FOUND` | 同上 |
| `stray_sighting` | 路人上报 | **不自动建档** | 仅写事件,`animal_id=NULL`,等 admin |
| `profile_build` | 系统内部(等价旧 `event_type='collect'`) | **不自动建档** | 同上 |
| `unknown` | 老数据 fallback / 未传 intent | **不自动建档** | 同上(默认 `lost` 行为向后兼容) |

> **代码位置**: `backend/src/animals/animals.service.ts:103-107`
> ```typescript
> status: dto.intent === 'found' ? AnimalStatus.FOUND : AnimalStatus.LOST,
> ```
> `backend/src/events/events.service.ts:57-67`(自动建档逻辑)

### 1.3 admin 审核动作映射(`PUT /v1/admin/events/:event_id/action` body.action)

| action | 调用 | event.status 终态 | is_duplicate | animal_id 来源 | UI 语义 |
|--------|------|-------------------|--------------|----------------|---------|
| `reject` | `rejectEvent` | `rejected` | 不变 | 不变 | 驳回,不入库 |
| `confirm` | `confirmEvent(event_id, animal_id)` | `duplicated` | `true` | 必须传 `animal_id`(绑到现成动物) | 确认合并到现有动物 |
| `merge` | 同 confirm(别名) | `duplicated` | `true` | 必须传 `animal_id` | UI 语义别名(让"合并"按钮文案独立) |
| `create_new` | `eventsService.createAnimalFromEvent` | `confirmed` | 不变 | 从 event 字段建 Animal + 自动关联 | "无匹配候选" → admin 手动建档 |

> **代码位置**: `backend/src/admin/admin.service.ts:195-225`(`dispatchEventAction` 实现)

### 1.4 状态机总览图

```
[用户提交事件]                    [admin 审核]                    [Animal 终态]
  intent + 数据                     PUT /events/:id/action          status
      │                                  │                            │
      ├─ intent=lost ───────────────────►│                            │
      │   EventsService.create            │                            │
      │   → 自动建档(status=LOST)         │                            │
      │   → 事件关联新 animal              │                            │
      │                                  │                            ▼
      │                                  │                          LOST (红)
      │                                  │
      ├─ intent=found ──────────────────►│                            │
      │   同上,但 status=FOUND           │                            ▼
      │                                  │                          FOUND (绿)
      │                                  │
      ├─ intent=stray_sighting ─────────►│ action=confirm/merge       │
      │   仅写事件,animal_id=NULL         │  → event.animal_id = 传参  │
      │   status=pending                 │  → event.status=duplicated │
      │                                  │                            ▼
      │                                  │                          已绑动物(状态不变)
      │                                  │
      │                                  │ action=create_new          │
      │                                  │  → 从 event 建新 Animal    │
      │                                  │  → event.animal_id = 新 ID  │
      │                                  │  → event.status=confirmed   │
      │                                  │                            ▼
      │                                  │                          新 Animal(status 由 event 字段推,默认 LOST)
      │
      └─ intent=profile_build / unknown ─►│ 同 stray_sighting 路径     │
                                         │                            │

后续: user 申请认领 → admin.approveClaim → Animal.status = claimed (橙)
```

## 7. 已知限制 & 用户实测反馈(从 `stage3-bugs-quick-test.md` L230-234)

> 用户在 2026-07-06 实测反推出来的核心问题:

1. **采集低分会直接生成新动物入库**(无需走 admin),但 admin 端仍可见此事件,"确认重复"无作用,**不更新已有动物状态**

   - 当前状态:**未实现 admin 端的"重复-更新状态+发通知"流程**,只是机械的 reject/confirm/create_new 三选一
   - **TODO 留给阶段 4**: admin 端 action 加 `update_status`(从 found → lost 或反之,触发通知)

2. **场景 ④ 验收(BUG-014 admin create_new)**: 后端代码已实现,UI 端"创建新动物"按钮**待验证**

3. **认领流程疑问**: 用户填"申请认领"后首页没立刻变认领中,等 admin 审核才显示;认领两来源(失主找回 / 无主动物被认领),是否应有"寄存"中间态?
   - 当前:claim 走 `claims` 表,`admin.approveClaim` 才转 `status=claimed`
   - **TODO 留给阶段 4**: 决定是否引入"寄存(pending_holding)"中间状态
