## 0. TL;DR — 一句话总览

**评论 ↔ 事件桥接新增 3 层空间校验**:
- 🆕 **10km 硬过滤**: 同 animal 召回的事件, 距离 > 10km 直接出局, 不参与评分
- 🆕 **本地 reverseGeocode**: 基于动物位置圈定 10km 内的 geo 词白名单, entity 匹配只在白名单内
- 🆕 **跨 animal 兜底保留软衰减**: 全局 30 天兜底召回 (跨 animal) 不硬切, 走原有 Haversine 软衰减
- 🐛 **修复 entities.json v2 加载 bug**: 之前 200+ 城市/区县 geo 词库在生产中**从未生效**, 阶段 E 一并修复

**带来的能力**:
- ✅ 武汉地址评论 → 上海事件 (600km) 被硬过滤, 不再生成跨城假阳性
- ✅ "我在武汉看到金毛" → 仅武汉/湖北本地事件可匹配, 跨城事件被 geo 白名单拒绝
- ✅ 街道/小区名误命中大幅下降 (如"望京"被识别为地名而非小区名)

**带来的局限** (见 §5):
- ⚠️ 依赖动物坐标已知; animal 没坐标时回退全集
- ⚠️ 街道级别精度缺失 (只到区县级)
- ⚠️ 跨省案例仍可能漏掉 (如"在哈尔滨看到一只金毛" 匹配到湖北动物)

## 1. 背景与问题

### 1.1 bug #2 软衰减的局限 (修复前)

`backend/src/comments/clue-bridge.service.ts` 第 7 步用 Haversine 公式对**远端事件做软衰减**:
- 5km 内不扣分
- 远端每 200km 扣约 0.01, 上限 0.3

**问题**:
- 上海事件 (距武汉 600km) 被扣 0.3 后, score = sentiment(0.5) + entity(0.3) - decay(0.3) = 0.5, **可能仍 ≥ threshold 0.5**, 仍生成跨城假阳性
- 算力浪费: 远端事件仍跑完 `matchEntity` (O(词条数 × 文本长度)) 才发现要被扣

### 1.2 探索阶段意外发现的事前 bug 🐛

`backend/data/dicts/entities.json` 实际是 `version: 2` (扩展了 `size` 和 `geo` 分类), 但 `dictionary.loader.ts:318` 校验**只接受 `version === 1`**。

**影响**: 整个 entities.json 被丢弃, 回退到 `BUILTIN_DEFAULTS`, 而 BUILTIN 的 entities **只有 breed/color/feature 三类, 没有 geo 和 size**。意味着 bug #2 修复时宣称的"geo 词库 200+ 城市"在生产中**从未生效**, 跨城假阳性的根因之一。

**修复**: 改为白名单 `[1, 2]`, 加 v2 加载单测, 警告语改为 `version=${v} not in [1,2]`。

> **代码位置**: `backend/src/comments/dictionary.loader.ts:318-323`

## 2. 三点创新

### 2.1 10km 硬过滤 (同 animal 召回)

**设计**: 在 `_tryMatch` 评分循环前, 对 `source='same'` 事件做距离检查, `> 10km` 直接跳过。

**实现**:
```typescript
// clue-bridge.service.ts:485-500
if (hardFilterOn && src === 'same' && animalLat && animalLng && ev.event_lat && ev.event_lng) {
  const distKm = haversineKm(animalLat, animalLng, ev.event_lat, ev.event_lng);
  if (distKm > hardFilterKm) {
    filteredOutCount++;
    continue; // 跳过, 不参与评分
  }
}
```

**配置**:
- `ScoringRules.geoHardFilterKm?: number` (默认 10, `0` = 关闭)
- 仅对 `source='same'` 生效, `source='fallback'` 走软衰减

**效果**:
- 远端事件不进入 `matchEntity` / 同义词 / 否定窗口计算, 算力 ↓ ~80%
- 跨城假阳性从 score 暴跌 0.3 改为完全不出现在 best 候选

### 2.2 本地 reverseGeocode (geo 词白名单)

**设计**: 基于动物位置, 推算"周围 N km 内"的 geo 词, 形成白名单。entity 匹配时, geo 分类词必须白名单内才记 hit, 非 geo (breed/color/feature/size) 不受限。

**实现**:
- 新建 `GeoResolverService`, 内置 60+ 核心城市/区县坐标 (城市级 ±5km, 区县级 ±10km)
- 网格倒排索引 (0.1° cell, 经度方向按 `cos(lat)` 自适应) + Haversine 二次过滤
- `clue-bridge.matchEntity()` 加 `allowedGeoWords?: Set<string>` 参数
- `ClueBridgeService.matchComment()` 调 `geoResolver.resolve(animalLat, animalLng, radiusKm)` 拿白名单, 注入 `_tryMatch` → `_score`

**关键设计权衡**:
- **零运行时依赖**: 60+ 坐标内嵌为 TS const, 不抓外部 API, 不读 JSON
- **空集保护**: animal 坐标缺失时, 白名单回退到**全集** (entities.json geo 全部词), 避免历史匹配全消失
- **漠河 53° 高纬度**: cellKey 经度方向按 `cos(lat)` 自适应, 不漏选

**性能**: 9 宫格 cell 内 < 50 词, Haversine 二次过滤, 实测 < 1ms / call (1000 次平均 0.3ms)

> **代码位置**: `backend/src/comments/geo-resolver.service.ts:331-365 resolve()`

### 2.3 跨 animal 兜底保留软衰减

**设计**: `source='fallback'` 的全局 30 天兜底召回 (跨 animal) 不走硬过滤, 保留原有 Haversine 软衰减。

**理由**:
- 用户在评论里描述的"看到金毛"可能匹配的是其他 animal 的走失单
- 例如同一地点不同 animal, 或漏报 animal_id
- 硬切会漏掉长尾命中, 软衰减保留概率性召回

**配置**:
- `geoFallbackSoftDecayKm?: number` (默认 50, 跨 animal 软衰减起点)
- `geoFallbackSoftDecayRate?: number` (默认 0.005/km, 与原 Haversine 软衰减斜率一致)

> **代码位置**: `backend/src/comments/clue-bridge.service.ts:355-365 第 7 步软衰减`

## 3. 与评分公式的衔接

### 3.1 评分公式更新 (v1.1 → v1.2)

| 版本 | 公式 | 适用 |
|------|------|------|
| **v1.1** | `score = sentiment + entity + (synonym \|\| 0) - (negation \|\| 0) + time - self + soft_geo_decay` | bug #2 修复后 |
| **v1.2** | `score = sentiment + entity_whitelist + (synonym \|\| 0) - (negation \|\| 0) + time - self + (soft_geo_decay \|\| 0)` | 阶段 E |
| | **变化** | |
| | 1. `entity` → `entity_whitelist` (geo 分类受白名单限制) | |
| | 2. `source='same'` 时, 第 7 步 `soft_geo_decay` 改为**硬过滤** (> 10km 直接出局) | |
| | 3. `source='fallback'` 时, 第 7 步仍走 `soft_geo_decay` | |

### 3.2 数据流

```
comment (用户评论)
  ↓
EventRecallService.recall(animalId, commentTime)
  ├─ Step 1: 同 animal 最近 5 条 → source='same'
  └─ Step 2: 30 天全局兜底 10 条 → source='fallback'
  ↓
ClueBridgeService.matchComment(comment, recentEvents)
  ├─ GeoResolverService.resolve(animalLat, animalLng, 10km) → allowedGeoWords
  ├─ for each event:
  │   ├─ source='same' AND dist > 10km → 跳过 (硬过滤)
  │   ├─ source='fallback' AND dist > 50km → 软衰减 (第 7 步)
  │   └─ _score(comment, event) → 用 allowedGeoWords 过滤 entity.geo
  └─ 选 best, 写 FileStateStore
  ↓
admin 审核 → confirmed → 落 DB (event + animal + comment)
```

## 5. 局限性 (诚实说明)

| 局限 | 等级 | 影响 | 缓解 |
|------|------|------|------|
| 依赖 animal 坐标已知 | 🟠 中 | 没坐标的 animal 走白名单全集, 效果退化为"不过滤" | 采集流程确保 animal 注册时定位 |
| 街道级别精度缺失 | 🟠 中 | "望京" / "光谷广场" 等小区名仍可能误命中 | 阶段 E+1 引入街道级坐标 |
| 跨省案例无解 | 🟡 低 | 跨省动物走失 (罕见) 会被硬过滤 | 跨 animal 兜底保留长尾 |
| 60+ 城市覆盖 | 🟡 低 | 277 个 geo 词条里约 50 个 (小城市/区) 没坐标, 不进白名单 | 后续按需扩充内嵌坐标表 |
| geo 词库冷启动 | 🟢 极低 | chokidar 热加载 dict 时, resolver 缓存需 rebuild | resolver 不缓存, 每次直接读 dict.getEntities() |
| 调试信息仅 console.debug | 🟢 极低 | 硬过滤跳过的具体事件不写 match_reasons | 后续可加 metrics 收集 |

## 附:与 02-架构设计 §3.2 融合算法的衔接

阶段 E 改动**完全兼容** 02-架构设计 §3.2 的融合算法框架, 只是在 entity 维度新增了"geo 子维度的空间约束":

| 维度 | v1.1 | v1.2 (阶段 E) |
|------|------|--------------|
| 文本 | sentiment + entity + synonym + negation | 同 (geo 子项受白名单限制) |
| 时间 | time_decay | 同 |
| 空间 | soft_geo_decay (Haversine) | **hard_filter (10km) + soft_decay (fallback)** |
| 身份 | self_match_penalty | 同 |
| 阈值 | score ≥ 0.5 → pending | 同 |

后续 v1.3+ 可在框架上扩展**新维度** (如"动物走失时长" / "评论时间差"), 阶段 E 已为这种扩展预留接口 (`ScoringRules` + `matchEntity` 可选参数 + 显式依赖注入)。
