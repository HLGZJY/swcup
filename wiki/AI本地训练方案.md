## 一、AI 在本项目里要做什么

AI 只解决一件事：**给狗鼻子拍张照片，告诉你是哪只狗**。

具体拆成三个功能：

| 功能 | 输入 | 输出 | 说明 |
|------|------|------|------|
| 活体检测 | 狗鼻子照片 | OK / 疑似照片欺骗 | 防止用网上图片冒充实拍 |
| 特征提取 | 狗鼻子照片 | 128维向量（余弦相似度用） | 鼻纹核心"身份证" |
| 四维度比对 | 128维向量 + GPS + 文本 + 原图 | Top-N 匹配列表 + 得分 | 融合判断是否重复 |

三个功能对应三个模型（或一个多任务模型），目前计划：

```
活体检测  ──→  特征提取  ──→  四维度融合比对
(简单二分类)    (MobileNetV2)       (加权得分)
```

## 二、两个开源项目仓库怎么用

项目里已有两个 AI 参考仓库，都来自学长/开源社区：

### 仓库A：`F:\课设与软件杯\ai防重复救助\dog-nose-print`

| 项目 | 内容 |
|------|------|
| 论文/思路 | VGG16 作为 backbone，提取 25088维向量 |
| 语言 | Python + FastAPI |
| 可用部分 | **可直接拿来用**：活体检测接口、特征提取接口、比对接口 |
| 局限 | 向量维度太高（25088），不适合移动端，推理慢 |

**怎么用**：直接部署这套 FastAPI 服务作为 AI 推理层，不需要自己写。队长拿来跑通、测试效果即可。

### 仓库B：`F:\课设与软件杯\ai防重复救助\pets-face-recognition`

| 项目 | 内容 |
|------|------|
| 论文/思路 | ResNet50 / MobileNetV2 + ArcFace度量学习，AUC=0.973 |
| 语言 | Python + PyTorch |
| 可用部分 | **核心训练流程**：两阶段训练（冻结backbone → 解冻微调）、ArcFace loss 实现、MobileNetV2 换成 ResNet50 |
| 局限 | 需要自己准备数据集，训练代码需要适配本项目鼻纹数据 |

**怎么用**：参考其训练 pipeline（两阶段、ArcFace loss、评测代码），迁移到本项目的 MobileNetV2 + 鼻纹数据集上。

### 两个仓库的关系

```
仓库A（dog-nose-print）：拿来部署 → 快速有可用服务
仓库B（pets-face-recognition）：参考训练 → 自己训练更好的模型
```

**推荐路径**：先用仓库A部署一个可用的 Baseline，同时用仓库B的训练流程逐步训练自己的模型，最终替换仓库A的服务。

## 三、能不能在笔记本电脑上本地训练？可以

### 硬件条件

| 配件 | 最低要求 | 推荐 | 说明 |
|------|----------|------|------|
| 内存 | 8GB | **16GB+** | PyTorch 数据加载吃内存 |
| 显存 | **GTX 1050 4GB+** | GTX 1660 / RTX 3060 | 显存决定 batch_size 上限 |
| 硬盘 | 256GB SSD | 512GB+ SSD | 数据集 + 模型权重存储 |
| CPU | i5 十代 | i7 / R7 | 数据预处理时用到 |

> **GPU 不是必须但强烈建议**：有 GPU 和没 GPU 训练时间差 10~20 倍。
> 没有 GPU 也可以跑，但 batch_size 要开很小（4~8），epoch 时间很长。

### 软件环境

```
Python 3.9+
PyTorch 2.0+（CUDA 11.8 或 CPU 版本）
torchvision（MobileNetV2 预训练权重）
FastAPI + uvicorn（部署推理服务）
Pillow + OpenCV（图像预处理）
scikit-learn（评测指标）
```

一行安装：
```bash
pip install torch torchvision fastapi uvicorn pillow opencv-python scikit-learn
```

### 数据集规模（边采集边标注，W2 任务）

| 阶段 | 数据量 | 训练时间（CPU） | 训练时间（GPU 4GB） |
|------|--------|----------------|-------------------|
| W3 Baseline | 500组（正负样本各半） | ~2~3天 | ~2~4小时 |
| W4 优化 | 1000+组 | ~5~7天 | ~6~10小时 |

> 训练时间仅为估算，实际受 batch_size、epoch 数影响。

## 四、任务分配建议（给队友）

### 队长负责（AI方向）

```
AI 训练任务 =====
1. 环境搭建（30分钟）
   - 安装 Python 3.9+ / PyTorch / CUDA（如有GPU）
   - 跑通仓库A的 FastAPI 服务，确认本地可访问
   - 下载仓库B的训练代码，读懂两阶段训练流程

2. 数据采集（进行中，W2核心）
   - 收集狗鼻子照片（500组起）
   - 边采集边用 labelme 或 LabelImg 标注鼻纹关键点
   - 整理成 "动物ID_序号.jpg" 命名格式

3. 模型训练（W3 ~ W4）
   - 用仓库B的 ArcFace loss 训练 MobileNetV2
   - 阶段一：冻结 backbone，5~10 epochs
   - 阶段二：解冻 backbone，lr=1e-4 微调
   - 输出：model.pth 权重文件

4. 推理服务部署（W3 ~ W4）
   - 基于仓库A的 FastAPI 改造成本项目接口
   - 输入：图片 → 输出：128维向量 + 活体检测结果
```

### 队员负责（前端方向，同步进行）

```
前端任务（不影响AI，但需了解AI接口）=
1. UniApp 项目初始化（参考学姐项目）
2. 调用 AI 接口的 Mock 数据页面（不依赖后端）
3. 与队长对接接口字段（向量维度、返回格式）
```

## 六、已知风险

| 风险 | 应对 |
|------|------|
| 笔记本 GPU 显存不够（<4GB） | 降低 batch_size 到 4，用梯度累积模拟大batch |
| CPU 训练太慢，坚持不下去 | 优先用 GPU，或租用 GPU 云服务器（AutoDL/极客云，便宜） |
| 数据集采集不够（<500组） | 网上开源数据集补充：Oxford-IIIT Pet Dataset（7000+张）可做预训练 |
| 活体检测模型缺失 | 仓库A已有，可直接用，后续再换更好方案 |
