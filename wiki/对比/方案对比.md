# 方案对比

> 本页对比整体技术方案，结合第十五届"中国软件杯"大赛要求和 8 周时间约束做决策。

## 方案变更说明（v1 → v2）

| v1 方案 | v2 变更 | 变更原因 |
|---------|---------|----------|
| 管理端独立 Web 后台 | 降级为内部测试账号演示 | 8 周内无法完成，聚焦核心功能 |
| INT8 量化/边缘部署 | 删除 | 初赛无需工程优化 |
| 兼容性测试报告、性能测试报告 | 删除 | 形式大于内容 |

## 架构方案对比

### 方案 A：单体架构（✅ 本项目采用）

**描述**：所有功能在一个后端服务中，前端独立，推理服务独立。

```
┌──────────────────┐     ┌──────────────────┐     ┌──────────────────┐
│   前端 App        │────▶│   后端 API       │────▶│  推理服务        │
│ (Uni-app/RN)     │◀────│ (Spring Boot)    │◀────│  (FastAPI)       │
└──────────────────┘     └────────┬─────────┘     └──────────────────┘
                                  │
                         ┌────────▼─────────┐
                         │   PostgreSQL     │
                         │  (含 pgvector)   │
                         └──────────────────┘
```

**优点**：

- 开发速度快，8 周内可完成
- 架构简单，易于演示和讲解
- 团队规模小（3人），单体复杂度可控

**缺点**：

- 扩展性有限（但初赛/决赛足够）
- 后端老师一人负责，单体更合适

### 方案 B：微服务架构

**描述**：将用户管理、宠物档案、鼻纹比对、救助记录拆分为独立服务。

**优点**：服务独立扩展，职责清晰

**缺点**：

- 开发和部署复杂度高
- 8 周时间不够
- 3 人团队维护成本高

**结论**：❌ 不适合，8 周内无法交付

### 方案 C：Serverless 架构

**描述**：使用云函数处理请求，向量数据库用云服务。

**优点**：按量付费，无需管理服务器

**缺点**：

- 冷启动延迟影响用户体验
- 依赖云厂商，评委演示可能受限
- 调试复杂

**结论**：❌ 不适合，比赛演示场景需要稳定响应

## AI 能力方案对比

| 方案 | 描述 | 适合本项目 | 说明 |
|------|------|------------|------|
| **自建 AI 模型** | 自主训练 MobileNetV2 | ✅ 是 | 核心差异点，体现 AI 能力 |
| 纯采购 API | 使用第三方图像识别 API | ❌ 否 | 通用 API 无法精准识别宠物鼻纹 |
| 混合方案 | API 处理通用逻辑 + 自建鼻纹层 | ❌ 否 | 增加复杂度，8 周内收益有限 |

**结论**：自建 AI 模型是本项目的核心亮点和竞争优势，必须保留。

## 最终架构决策

| 层级        | 技术选型                   | 决策依据           |
| --------- | ---------------------- | -------------- |
| **AI 模型** | MobileNetV2 迁移学习       | 轻量、移动端友好、核心亮点  |
| **推理服务**  | FastAPI                | Python 生态、部署简单 |
| **后端**    | Spring Boot / Flask    | 老师擅长，快速开发      |
| **数据库**   | PostgreSQL + pgvector  | 支持向量检索，一体化方案   |
| **前端**    | Uni-app / React Native | 跨平台，演示方便       |
| **部署**    | Docker 单机部署            | 评委可本地运行演示      |
