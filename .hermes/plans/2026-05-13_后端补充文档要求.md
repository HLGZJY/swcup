# 后端补充文档要求 — 供前后端联调

> 发送给：后端开发（老师 Agent）
> 发送人：统筹协调者
> 日期：2026-05-13
> 背景：前端即将从 Mock 切换到真实接口，需要后端补充以下 5 类文档

---

## 要求一：各接口真实请求/响应示例

**格式**：每个接口一段，包含：
1. 请求 method + URL + Headers（如有特殊 header）
2. 完整 Body / Query 示例（JSON 格式，所有字段赋值）
3. 成功的完整响应（含 code: 0）
4. 失败的完整响应（至少 1 个错误示例）

**要求**：覆盖全部 23 个接口，用户端 11 个 + 管理端 12 个。

---

## 要求二：错误码和报错场景说明

**格式**：表格

| code | message | 含义 | 前端处理方式 |
|------|---------|------|-------------|
| 0 | success | 成功 | - |
| 40001 | 参数缺失 | 缺少必填字段 | 提示用户 |
| 40101 | Token 过期 | JWT 过期 | 跳转登录页 |
| 40102 | Token 无效 | 伪造/篡改 | 跳转登录页 |
| 40303 | 无权限 | role 不是 admin | 提示无权限 |
| 40401 | 资源不存在 | 动物/事件/认领不存在 | 提示已删除 |
| 50001 | 服务器错误 | 后端异常 | 提示稍后重试 |

**要求**：
- 至少 15 个错误码
- 明确说明 Token 过期时后端返回的 HTTP Status Code 是多少（200 还是 401？）
- 说明网络超时（如 AI 服务超时）时前端收到什么

---

## 要求三：文件上传规格说明

鼻纹采集涉及图片上传，请说明：

1. 上传接口路径和 HTTP 方法
2. 是否 `multipart/form-data` 还是 base64 放在 body 里
3. 文件大小上限（MB）
4. 支持的图片格式
5. 额外必填字段（如 animal_id、device_id、timestamp 等）
6. liveness 活体检测是否有特殊要求（拍照角度、次数）

---

## 要求四：认证流程补充说明

1. **Token 存储方式**：前端应该存在 localStorage 还是 cookie？建议明确
2. **请求默认行为**：后端是否所有接口都在响应头返回新 token？还是前端自己处理刷新？
3. **Token 过期处理**：后端检测到过期时，响应的 HTTP Status Code 是多少？code/message 字段内容是什么？
4. **登录态失效**：后端什么情况下会让已登录的 token 失效？（换设备？手动登出？）
5. **测试账号的 role**：3 个测试账号的 role 字段值是什么？（admin / user / 其他）

---
