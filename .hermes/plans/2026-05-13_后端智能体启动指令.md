## 核心业务规则

### 1. 统一响应格式
```typescript
// 所有接口统一返回
{ code: 0, message: 'success', data: {...} }
// 错误时
{ code: 400/401/403/404/500, message: '错误描述', data: null }
```

### 2. JWT 认证
- 登录成功后返回 `token`
- 前端请求时 Header：`Authorization: Bearer <token>`
- `/api/admin/*` 需要额外校验 `role = 'admin'`

### 3. 鼻纹采集/比对（AI未就绪时的降级方案）
- AI服务尚未就绪，先返回mock数据，保证前端可联调
- `/api/nose/collect` 返回：`{ vector_id: uuid, confidence_score: 0.92, liveness_passed: true }`
- `/api/nose/compare` 返回：`{ total: 3, results: [...], threshold_confirmed: 0.88, threshold_suspected: 0.75 }`
- 等AI模型训练完成后，在 `nose.service.ts` 中替换为真实调用

### 4. 四维度融合得分（后端计算）
```
fusion_score = 0.40 × sim_vector + 0.20 × S_location + 0.20 × sim_image + 0.20 × sim_text
S_location = max(0, 1 - (gps_distance_m - 500) / 1000)  // 500m内满分，1500m外0分
```
- GPS距离用 Haversine 公式计算
- 文本相似度：品种+颜色+性别关键词重合度

### 5. 事件状态枚举
- `pending` / `confirmed` / `duplicated` / `linked` / `resolved` / `rejected`

### 6. 动物状态枚举
- `lost` / `found` / `claimed` / `archived`

## 开发步骤

1. **初始化 NestJS 项目**（参考 `docs/后端启动配置指南.md`）
   ```bash
   cd /mnt/f/swcup2026/backend
   npx @nestjs/cli new . --package-manager npm --skip-git
   npm install @nestjs/typeorm typeorm mysql2 @nestjs/jwt @nestjs/passport passport passport-jwt class-validator class-transformer @nestjs/swagger multer uuid
   ```

2. **配置 .env**（参考 `docs/后端启动配置指南.md`）
   ```
   PORT=3000
   DB_HOST=localhost
   DB_PORT=3306
   DB_USER=root
   DB_PASSWORD=your_password
   DB_NAME=nose_rescue
   JWT_SECRET=your_secret_key
   JWT_EXPIRES_IN=7d
   ```

3. **执行建表脚本**
   - 先在 MySQL 创建数据库：`CREATE DATABASE IF NOT EXISTS nose_rescue`
   - 然后执行 `docs/数据库建表脚本.md` 中的建表 SQL

4. **按模块开发**（参考 `docs/前端接口文档-给老师.md`）
   - 先完成 Auth 模块（登录/注册）
   - 再完成 Animals 模块
   - 再完成 Events 模块
   - 再完成 Claims 模块
   - 再完成 Users 模块
   - 最后完成 Admin 模块（含角色校验）

5. **AI 相关先留 mock**（等模型就绪后替换）
   - `nose.service.ts` 中 `/api/nose/collect` 和 `/api/nose/compare` 返回 mock 数据

6. **启动验证**
   ```bash
   npm run start:dev
   # 访问 http://localhost:3000/api-docs 查看 Swagger 文档
   # 访问 http://localhost:3000/api/health 健康检查
   ```

## 注意事项

1. **不要等 AI 模型** — AI 相关接口先返回 mock，不阻塞前端联调
2. **不要改前端代码** — 只开发后端，前端由前端队员维护
3. **数据库外键** — 建表脚本中 `animals.primary_nose_id` 外键在 `nose_features` 之后才能加，后端 Entity 先不加这个外键，等建完表再单独处理
4. **统一响应格式** — 用 NestJS 全局拦截器统一包装，不需要每个路由手动处理
5. **Swagger 文档** — 所有 DTO 要有 `@ApiProperty` 注解，方便前端查阅
