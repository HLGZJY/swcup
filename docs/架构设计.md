## 1. 系统架构概述

### 1.1 架构风格

**前后端分离 + AI 服务化**

```
┌─────────────────────────────────────────────────────────────┐
│                      用户层                                    │
│   ┌──────────────┐            ┌──────────────┐              │
│   │  用户端小程序   │            │  管理端小程序   │              │
│   │（普通救助者）   │            │（管理员/救助站）│              │
│   └──────┬───────┘            └──────┬───────┘              │
│          │                           │                      │
│          └─────────── REST API ───────┘                      │
│                         │                                     │
│              ┌──────────┴──────────┐                        │
│              │                     │                         │
│        Node.js 后端           FastAPI AI 服务                  │
│        (Express)              (Python/PyTorch)                │
│              │                     │                         │
│              └──────────┬──────────┘                        │
│                         │                                     │
│                   MySQL 数据库                                  │
│          （档案 + 事件 + 用户 + 512维向量）                      │
└─────────────────────────────────────────────────────────────┘
```

### 1.2 模块职责

| 模块 | 技术栈 | 职责 | 部署 |
|------|--------|------|------|
| 用户端小程序 | UniApp + Vue3 | 鼻纹采集、AI比对、认领流程 | 微信小程序平台 |
| 管理端小程序 | UniApp + Vue3 | 动物档案管理、AI融合审核、数据统计 | 微信小程序平台 |
| 后端 API | Node.js (Express) + MySQL | 业务逻辑、REST API、数据库读写 | 服务器 |
| AI 推理服务 | FastAPI + PyTorch | 活体检测、特征提取、四维度融合计算 | Python 服务（CPU 推理） |

### 1.3 前后端通信协议

- **协议**：HTTP RESTful
- **数据格式**：JSON
- **认证**：JWT（待定，简单 token 也可）
- **AI 服务调用**：后端通过内部 HTTP 请求调用 FastAPI，不暴露公网

### 3.2 核心 API

#### 3.2.1 鼻纹采集

```
POST /api/nose/collect
```

**请求体**：

```json
{
  "nose_photo": "base64或file",
  "species": "dog",
  "location_lat": 39.9042,
  "location_lng": 116.4074,
  "description": "鼻纹正面照，光照良好"
}
```

**处理流程**：

```
1. 后端接收图片 → 2. 调用 FastAPI /detect/liveness → 3. 活体通过后调用 /extract/feature
4. 存储向量到 nose_features 表 → 5. 返回 { vector_id, confidence_score }
```

**响应**：

```json
{
  "code": 0,
  "message": "采集成功",
  "data": {
    "vector_id": "v1a2b3c4-...",
    "confidence_score": 0.92,
    "liveness_passed": true
  }
}
```

#### 3.2.2 鼻纹比对（融合四维度）

```
POST /api/nose/compare
```

**请求体**：

```json
{
  "vector_id": "v1a2b3c4-...",
  "species": "dog",
  "location_lat": 39.9042,
  "location_lng": 116.4074,
  "description": "黄白相间",
  "photo_base64": "..."
}
```

**处理流程**：

```
1. 后端 → FastAPI /extract/feature（图）   → 512维向量
2. 后端 → MySQL 查询同物种 Top-50 候选向量
3. 后端计算四维度融合得分：
   - 向量相似度（余弦）：权重 40%
   - GPS 距离：权重 20%
   - 整图相似度（pHash）：权重 20%
   - 文本描述重合度：权重 20%
4. 排序返回 Top-N 结果
```

**响应**：

```json
{
  "code": 0,
  "message": "比对完成",
  "data": {
    "total": 3,
    "results": [
      {
        "animal_id": "a1b2c3d4-...",
        "fusion_score": 0.91,
        "vector_similarity": 0.95,
        "gps_distance_m": 320,
        "image_similarity": 0.88,
        "text_match_rate": 0.80,
        "animal": { "species": "dog", "breed": "中华田园犬", "status": "lost" }
      }
    ],
    "threshold_confirmed": 0.88,
    "threshold_suspected": 0.75
  }
}
```

### 3.3 AI 服务接口（FastAPI，端口 8000）

内部调用，后端 Node.js 通过 HTTP 请求访问，不对外暴露。

| 端点 | 方法 | 说明 | 请求体 | 响应 |
|------|------|------|--------|------|
| `/detect/liveness` | POST | 图片质量检测（简化活体） | `{image: base64 str}` | `{quality: str, score: float}` |
| `/extract/feature` | POST | 特征提取，输出 512 维向量 | `{image: base64 str}` | `{vector: list[512], shape: [512]}` |
| `/compare` | POST | 两向量余弦相似度比对 | `{vector_a: list[512], vector_b: list[512]}` | `{similarity: float, distance: float}` |
| `/health` | GET | 健康检查 | - | `{status: "ok"}` |

> 注：融合打分 `fusion_score = 0.40×sim_vector + 0.20×S_location + 0.20×sim_image + 0.20×sim_text` 在后端 Node.js 计算，不在 AI 服务内。

## 4. 四维度融合策略

### 4.1 公式

```
fusion_score = 0.5 × sim_vector + 0.3 × S_location + 0.2 × sim_text
```

> **2026-05-23 修正**：取消"图像哈希"维度（原占位值）。现有 AI 模型仅支持鼻纹特征比对，不支持全身照相似度比对。三维度均为真实值。

### 4.2 各维度计算

| 维度 | 计算方式 | 数据来源 |
|------|----------|----------|
| sim_vector | 余弦相似度：`dot(v1,v2) / (\|v1\|\|v2\|)` | 512 维向量，AI `/extract/feature` + 后端计算 |
| S_location | `max(0, min(1, 1-(d-500)/1000))`，d=Haversine距离(m) | Haversine 公式，500m内满分，1500m+得0分 |
| sim_text | 关键词重合率 | breed + color + gender + tags 重合度 |

**AI 输出的人类可审核原则**：品种分类结果作为表单预填建议，用户可修改，不覆盖用户输入；质量检测不通过时阻止进入下一步，不自动修复图片。

### 4.3 阈值判定

| fusion_score | 判定 | 系统行为 |
|--------------|------|----------|
| ≥ 0.88 | **确认重复** | 自动合并，管理员通知 |
| 0.75–0.88 | **疑似重复** | 推送给管理员人工审核（含候选列表） |
| < 0.75 | **无匹配** | 询问用户是否创建新档案（方案B），用户确认后新建动物档案 |
