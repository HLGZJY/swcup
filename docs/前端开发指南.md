> 本文档给前端（队员）使用，整理了启动前端开发所需的全部技术输入。
> 前端开发完全使用 Mock 数据，不依赖后端进度，可以立即开始。

### 4.3 鼻纹比对（四维度融合）

```
POST /api/nose/compare
```

**请求 Mock：**
```json
{
  "vector_id": "v1a2b3c4-xxxx",
  "species": "dog",
  "location_lat": 39.9042,
  "location_lng": 116.4074,
  "description": "黄白相间",
  "photo_base64": "..."
}
```

**响应 Mock：**
```json
{
  "code": 0,
  "message": "比对完成",
  "data": {
    "total": 3,
    "results": [
      {
        "animal_id": "a1b2c3d4-xxxx",
        "fusion_score": 0.91,             // 融合总分 0-1
        "vector_similarity": 0.95,       // 向量相似度（余弦）
        "gps_distance_m": 320,            // GPS距离（米）
        "image_similarity": 0.88,        // 整图相似度（pHash）
        "text_match_rate": 0.80,          // 文本描述重合度
        "animal": {
          "animal_id": "a1b2c3d4-xxxx",
          "species": "dog",
          "breed": "中华田园犬",
          "color": "黄白相间",
          "gender": "male",
          "status": "lost",
          "first_seen_at": "2026-05-01T10:00:00Z",
          "address": "朝阳区某街道"
        }
      }
    ],
    "threshold_confirmed": 0.88,          // 确认重复阈值
    "threshold_suspected": 0.75           // 疑似重复阈值
  }
}
```

**融合得分计算公式：**
```
fusion_score = 0.40 × sim_vector + 0.20 × S_location + 0.20 × sim_image + 0.20 × sim_text
```

| 维度 | 权重 | 说明 |
|------|------|------|
| sim_vector | 40% | 余弦相似度，512维特征向量 |
| S_location | 20% | GPS距离，500m内满分，1500m外0分 |
| sim_image | 20% | pHash感知哈希相似度 |
| sim_text | 20% | 品种+颜色+性别+标签关键词重合度 |

**判定规则：**
- fusion_score ≥ 0.88 → 确认重复（自动合并）
- 0.75 ≤ fusion_score < 0.88 → 疑似重复（管理员审核）
- fusion_score < 0.75 → 无匹配（新建档案）

## 6. 三大核心业务流程（前端路由）

### 流程一：鼻纹采集 → AI比对 → 结果展示

```
首页 (index)
  ↓ 点击"采集鼻纹"
采集引导页 (collect/index)
  → 拍摄鼻纹照片
  → 调用 /api/nose/collect
  ↓ 采集成功后
比对结果页 (collect/result)
  → 调用 /api/nose/compare
  → 展示融合得分 Top-N
  → fusion_score ≥ 0.88 → 显示"确认重复"
  → 0.75 ≤ fusion_score < 0.88 → 显示"疑似重复，请审核"
  → fusion_score < 0.75 → 显示"未匹配，可新建档案"
```

### 流程二：救助事件上报

```
采集结果页
  → 点击"上报救助"
  ↓
填写事件信息（动物信息+照片+位置）
  ↓
提交 → POST /api/events
  → 自动触发比对
  → 返回 is_duplicate / fusion_score
  → 引导用户进入对应流程
```

### 流程三：认领流程

```
动物详情页 (animal-detail)
  → 点击"我要认领"
认领流程页 (claim/index)
  → 填写认领信息 + 证明材料
  → POST /api/claims
  → 等待管理员审核（status: pending）
管理端审核 → PUT /api/admin/claims/:id/approve
  → 用户收到通知 → status: approved
```

## 7. 页面间数据传递规范

页面间跳转时，通过 **URL Query 参数** 传递必要数据，**禁止**使用变量引用（UniApp 页面是跨文件隔离的）。

### 方式一：URL Query 参数（推荐）

```javascript
// 跳转时
uni.navigateTo({
  url: `/pages/collect/result?vector_id=${vectorId}&species=dog`
})

// 目标页 onLoad 中接收
onLoad((options) => {
  const { vector_id, species } = options
  // 使用 vector_id 调用比对接口
})
```

### 方式二：Storage（用于需跨 Tab 共享的数据）

```javascript
// 存储（登录态）
uni.setStorageSync('token', token)
uni.setStorageSync('user_info', userInfo)

// 读取
const token = uni.getStorageSync('token')
```

### 采集流程数据流

```
首页 → 点击"采集鼻纹"按钮
  → 跳转 pages/collect/index（选物种 + 拍鼻纹）
  → 提交采集 → POST /api/nose/collect
  → 获取 vector_id
  → 跳转 pages/collect/result?vector_id=${vector_id}&species=${species}
  → result.vue 读取参数
  → 跳转 pages/collect/result
  → 调用 POST /api/nose/compare({ vector_id, species, ... })
  → 展示结果
```

### 认领流程数据流

```
动物详情页 → 点击"我要认领"
  → 跳转 pages/claim/index?animal_id=${animalId}
  → claim.vue 读取 animal_id，调详情接口
  → 用户填写表单
  → 提交 POST /api/claims
  → 成功 → 跳转个人中心 pages/user/index
```

## 8. GPS 维度得分计算公式

按 `wiki/四维度融合策略.md` 的精确公式实现：

```javascript
/**
 * 计算位置维度得分 S_location
 * @param {number} distanceM - 两点距离（米）
 * @returns {number} 得分 0~1
 */
function calcLocationScore(distanceM) {
  if (distanceM <= 500) return 1.0
  if (distanceM >= 1500) return 0
  return Math.max(0, 1 - (distanceM - 500) / 1000)
}

/**
 * 融合得分（四维度加权）
 */
function calcFusionScore(r) {
  const S_location = calcLocationScore(r.gps_distance_m)
  return (
    0.40 * r.vector_similarity +  // 向量相似度
    0.20 * S_location +            // 位置得分
    0.20 * r.image_similarity +  // 图像相似度
    0.20 * r.text_match_rate     // 文本匹配度
  )
}
```

**阈值判定**：
- fusion_score ≥ 0.88 → 确认重复（自动合并）
- 0.75 ≤ fusion_score < 0.88 → 疑似重复（管理员审核）
- fusion_score < 0.75 → 无匹配（新建档案）
