## 一、技术约束

| 约束 | 说明 |
|------|------|
| 协议 | HTTP RESTful |
| 数据格式 | JSON |
| 认证 | JWT Token（建议） |
| 文件上传 | Multipart form-data 或 Base64（鼻纹照片较小，Base64 更简单） |
| 图片存储 | 上传至本地或 OSS，返回 URL 字符串 |
| AI 服务 | 后端通过内部 HTTP 调用 FastAPI（`http://localhost:8000`），不暴露公网 |
| CORS | 允许小程序域名（`servicewechat.com` 等） |
| 编码 | 统一 UTF-8 |

## 二、统一响应格式

所有接口统一使用以下响应结构：

```json
{
  "code": 0,
  "message": "操作成功",
  "data": { ... }
}
```

| code | 含义 |
|------|------|
| 0 | 成功 |
| 400 | 参数错误 |
| 401 | 未登录 / Token 无效 |
| 403 | 无权限 |
| 404 | 资源不存在 |
| 500 | 服务器内部错误 |

### 3.2 鼻纹采集（用户端）

#### 采集鼻纹
```
POST /api/nose/collect
```
**请求：**
```json
{
  "nose_photo": "base64字符串或文件上传",
  "species": "dog",
  "location_lat": 39.9042,
  "location_lng": 116.4074,
  "description": "鼻纹正面照，光照良好"
}
```
**处理流程（后端内部逻辑）：**
```
1. 接收图片
2. 调用 FastAPI /api/detect/liveness（活体检测）
3. 活体通过后调用 FastAPI /api/extract/feature（提取512维向量）
4. 存储向量到 nose_features 表
5. 返回结果
```
**响应：**
```json
{
  "code": 0,
  "message": "采集成功",
  "data": {
    "vector_id": "v1a2b3c4-xxxx",
    "confidence_score": 0.92,
    "liveness_passed": true
  }
}
```

### 3.3 鼻纹比对（用户端）

#### 比对鼻纹（四维度融合）
```
POST /api/nose/compare
```
**请求：**
```json
{
  "vector_id": "v1a2b3c4-xxxx",
  "species": "dog",
  "location_lat": 39.9042,
  "location_lng": 116.4074,
  "description": "黄白相间，中华田园犬",
  "photo_base64": "base64字符串（整图，用于pHash比对）"
}
```
**处理流程（后端内部逻辑）：**
```
1. 用 vector_id 从 nose_features 表查出向量
2. 从 animals 表查出同物种 top-50 候选
3. 调用 FastAPI /api/compare（计算向量相似度）
4. 后端计算四维度融合得分：
   - sim_vector: 余弦相似度（权重40%）
   - S_location: GPS距离得分（权重20%，500m内满分）
   - sim_image: pHash整图相似度（权重20%）
   - sim_text: 品种+颜色+性别关键词重合度（权重20%）
5. 按 fusion_score 降序返回 top-N
```
**响应：**
```json
{
  "code": 0,
  "message": "比对完成",
  "data": {
    "total": 3,
    "results": [
      {
        "animal_id": "a001",
        "fusion_score": 0.91,
        "vector_similarity": 0.95,
        "gps_distance_m": 320,
        "image_similarity": 0.88,
        "text_match_rate": 0.80,
        "animal": {
          "animal_id": "a001",
          "species": "dog",
          "breed": "中华田园犬",
          "color": "黄白相间",
          "gender": "male",
          "status": "lost",
          "first_seen_at": "2026-05-01T10:00:00Z",
          "address": "朝阳区某街道"
        }
      }
    ],
    "threshold_confirmed": 0.88,
    "threshold_suspected": 0.75
  }
}
```

**融合公式：**
```
S_location = max(0, 1 - (distance_m - 500) / 1000)   // 500m内满分，1500m外0分
fusion_score = 0.40 × sim_vector + 0.20 × S_location + 0.20 × sim_image + 0.20 × sim_text
```

**判定规则：**
| 融合得分 | 判定 | 动作 |
|----------|------|------|
| ≥ 0.88 | 确认重复 | 自动合并 |
| 0.75 ~ 0.88 | 疑似重复 | 管理员审核 |
| < 0.75 | 无匹配 | 新建档案 |

## 四、AI 服务调用约定

后端需要调用 AI 推理服务（FastAPI），约定如下：

| AI 端点 | 用途 | 调用方式 |
|---------|------|----------|
| `POST /extract/feature` | 提取512维鼻纹向量 | `{"image": "base64或URL"}` → `{"vector": [0.1, ...], "dimension": 512}` |
| `POST /detect/liveness` | 活体检测 | `{"image": "base64"}` → `{"passed": true, "confidence": 0.92}` |
| `POST /compare/vector` | 向量相似度计算 | `{"vector_a": [...], "vector_b": [...]} → {"similarity": 0.95}` |

**建议**：后端对 AI 服务做内部封装，不直接暴露给前端。

## 七、前端发现的后端需注意问题

| # | 问题 | 说明 |
|---|------|------|
| 1 | AI 服务需后端代调 | 小程序不能直接请求 AI 服务（跨域+认证），必须通过后端转发 |
| 2 | 鼻纹照片存储 | 小程序拍照后为 base64，需后端存储并返回 URL |
| 3 | GPS 坐标精度 | 建议存 DECIMAL(10,8) / DECIMAL(11,8)，GPS 距离计算需转换 |
| 4 | 融合得分在后端算 | `fusion_score` 计算逻辑在后端，不在前端 |
| 5 | 事件上报自动建档 | POST /api/events 后需自动触发比对并创建 animal 记录 |
| 6 | 管理员权限控制 | `/api/admin/*` 接口需校验 role=admin |
