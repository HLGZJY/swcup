# 后端认证流程说明

## 一、Token 存储方式

**推荐：localStorage**

- 前端将登录成功后后端返回的 `token` 存储在 `localStorage.setItem('token', data.token)`
- 每次请求从 localStorage 取出，放到 HTTP Header：`Authorization: Bearer <token>`
- 不推荐 cookie，因为后端没有设置 httpOnly/secure/sameSite 策略

**存储示例**
```javascript
// 登录成功后
localStorage.setItem('token', response.data.token);

// 请求时
headers: {
  'Authorization': 'Bearer ' + localStorage.getItem('token')
}

// 登出时
localStorage.removeItem('token');
```

---

## 二、请求时 Token 携带方式

所有需要认证的接口都必须在 Header 中携带 Token：

```
Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
```

**无需特殊 header**，`Authorization` 是标准 HTTP 头，值格式为 `Bearer <token>`。

### 公开接口（无需 Token）

以下接口不需要认证，可以在请求时不带 Token：
- `POST /auth/login`
- `POST /auth/register`
- `GET /animals`（列表）
- `GET /animals/:animal_id`（详情）
- `POST /nose/collect`
- `POST /nose/compare`

### 需要 Token 的接口

除上述公开接口外，其他所有接口均需带 Token。

---

## 三、Token 刷新策略

**当前实现：无主动刷新，7天过期后重新登录**

- JWT 有效期：7 天（`expiresIn: '7d'`）
- 后端不会主动刷新 token，也不主动返回新 token
- 前端需要在 token 即将过期时（如剩余 1 天）引导用户重新登录

**未来可扩展**：如果需要 token 刷新机制，可以在每个响应头中携带新 token（需后端配合）。

---

## 四、Token 过期时的响应

### 后端检测到 JWT 过期

- **HTTP Status Code**：401
- **响应 body**：
  ```json
  {
    "code": 40101,
    "message": "Token 过期",
    "data": null
  }
  ```

### 后端检测到 JWT 无效（伪造/篡改/未提供）

- **HTTP Status Code**：401
- **响应 body**：
  ```json
  {
    "code": 40102,
    "message": "Token 无效",
    "data": null
  }
  ```

### 前端处理逻辑

```javascript
if (response.code === 40101 || response.code === 40102) {
  localStorage.removeItem('token');
  // 跳转登录页
  window.location.href = '/login';
}
```

---

## 五、Token 失效场景

### 会导致 Token 失效的情况

1. **JWT 过期**：默认 7 天后过期
2. **用户修改密码**：后端不会主动让其他 token 失效（当前实现），但建议前端主动清除
3. **服务端重启**：不影响已有 token

### 不会导致 Token 失效的情况

- 用户换设备（同一账号可多处登录）
- 手动登出（前端清除 localStorage，后端不保存 token 黑名单）

## 七、登录流程完整示例

```
1. 前端 POST /auth/login {"phone":"13900000001","password":"password123"}
2. 后端验证通过，返回 {"code":0,"message":"success","data":{"token":"...","user":{...}}}
3. 前端 localStorage.setItem('token', token)
4. 后续请求 Header 带 Authorization: Bearer <token>
5. 后端 JwtAuthGuard 校验 token，合法则放行，非法/过期返回 401
```
