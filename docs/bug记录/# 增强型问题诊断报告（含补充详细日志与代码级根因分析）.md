## 四、精准修复方案（含代码修改位置建议）

### 🔧 修复 1：普通用户创建动物草稿（解决 403）

- **文件**：`animals.controller.ts` 或新建 `draft.controller.ts`
- **方案**：新增 `POST /v1/animals/draft`，权限设置为 `@Roles('guest', 'user')`，数据状态默认为 `status: 'pending_approval'`。
- **前端调整**：采集结果页点击“创建动物”时，调用 `/v1/animals/draft` 而非 `/v2/animals`。

### 🔧 修复 2：发现页无候选时创建待审核任务（解决 Admin 无入口）

- **文件**：`EventsService.processEvent()`
- **方案**：
  ```typescript
  if (candidates_count === 0) {
      // 新增逻辑：自动生成一个 pending_animal_draft 记录，关联 event_id
      await this.draftService.createFromEvent(eventId, { nose_photo: null, ... });
      // 发送通知给 Admin 审核列表
  }
  ```
- **Admin 端**：审核列表新增“待创建动物”Tab，点击后补全信息并发布。

### 🔧 修复 3：鼻纹改为可选项 + 三种匹配策略

- **文件**：`NoseService.collect()` + `MatchingService`
- **方案**：
  - 前端取消 `required: true`。
  - `MatchingService` 增加策略路由：
    - 传入 `nose_vector` → 执行 1:N 鼻纹比对。
    - 未传入 `nose_vector` → 执行图片+GPS+文本多模态比对。
    - 混合场景：先用鼻纹比对，若分数低于阈值，再降级为多模态比对。

### 🔧 修复 4：首次采集 400（认证时序）

- **文件**：`AuthGuard` 或 `NoseService`
- **方案**：在 `NoseService.collect` 入口处，若 `user` 为空且存在 `device_id`，自动调用 `SessionService.createGuestSession(device_id)` 生成临时身份，**不再抛出异常**。

### 🔧 修复 5：防止重复提交

- **后端**：Redis 缓存 `nose_photo` 的 MD5，有效期 5 分钟，重复提交返回已有 `vector_id`。
- **前端**：点击“比对”后立即 `disabled=true`，直至请求完成。
