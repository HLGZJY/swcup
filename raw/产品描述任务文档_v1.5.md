# 产品描述任务文档
## AI 驱动的流浪动物防重复救助系统

---

## 一、项目背景与价值主张

### 社会痛点
当前流浪动物救助体系存在严重的**资源浪费问题**：
- 同一只动物被多次重复救助的现象普遍
- 救助者花费大量时间精力在已救助动物上
- 有限的救助资源被无效消耗
- 民间救助组织间信息不通，形成"信息孤岛"

### 解决方案
本项目通过 **AI 多维度联合查重** 技术（特征向量 + 鼻纹 + GPS定位 + 图像相似度），构建流浪动物防重复救助平台，实现：
- **误报重报率从 X% 降至 1% 以内**（目标指标）
- **释放千万级救助资金**（社会价值）
- 救助资源精准对接，减少无效劳动

### 核心创新亮点

| 维度 | 传统方案 | 本项目 |
|------|----------|--------|
| 重复检测 | 人工比对，靠眼睛 | AI 多维度综合判断（特征+鼻纹+定位+图片） |
| 技术路线 | 调用商业API，成本高/不支持个体识别 | 轻量化自训练模型，0成本，支持个体识别 |
| 准确性 | 低，受主观影响大 | 高，客观可量化（余弦相似度） |
| 信息孤岛 | 各平台独立 | 统一平台整合 |

## 二、产品定义

### 产品名称
**"鼻纹智救"** — AI 流浪动物精准救助平台

（备选：**"寻它"**、**"救助智联"**）

### 目标用户
1. **普通救助者**：发现流浪动物的个人，希望快速确认是否已被救助
2. **救助站/民间组织**：需要协调资源，避免重复救助
3. **动物保护协会**：监管流浪动物数据，统计分析

### 核心用户故事

**作为救助者：**
> "我发现一只流浪猫，想发布求助。但系统告诉我，这只猫 3 天前已在 500 米外被报告过。我选择联系原救助者，而不是重复行动。"

**作为管理员：**
> "系统 AI 提示两条留言高度相似（特征相似度 95%，定位相距 200 米），我一键合并，避免信息重复。"

### 动物状态流转规则

一只动物从失踪到回家，状态流转规则如下：

```
[走丢] → [已找到] → [已认领] → [已归档]
  ↑           ↓
  ← ← ← ← ← ← ←
（超时未匹配，自动继续寻找）
```

| 状态 | 说明 | 可流转条件 |
|------|------|-----------|
| 走丢（默认） | 刚发布留言，等待救助 | 被标记为"已找到"，或 90 天超时 |
| 已找到 | 有人发现了这只动物，等待主人认领 | 原主人认领 → 已认领；超时 → 继续等待 |
| 已认领 | 原主人与救助者完成交接 | 30 天无异常 → 已归档 |
| 已归档 | 历史记录，保留数据用于统计 | 不可流转，保留鼻纹向量用于模型改进 |
| 超时未匹配 | 90 天内无任何匹配结果 | 用户可重新发布，或系统自动标记 |

**异常处理：**
- 管理员发现留言信息虚假/恶意 → 直接删除，状态终止
- 多条留言指向同一动物 → AI 提示合并，用户/管理员确认后合并
- 原主人和救助者同时声称认领权 → 标记"争议中"，管理员人工判断

#### AI 多维度重复检测（综合评分）

本项目采用**多数据融合**策略，综合以下维度判断重复：

1. **AI 鼻纹特征向量比对**（核心，权重 40%）
   - 使用 MobileNetV2 迁移学习（轻量化，CPU 可推理）
   - 提取鼻部区域 128 维特征向量
   - 余弦相似度计算，判断是否为同一动物
   - 阈值通过验证集实验确定（初定 0.82-0.88 范围，待实测校准）

2. **定位重合度**（权重 20%）
   - GPS 坐标距离计算（用户发布时 GPS 自动获取，非手动选择）
   - 500 米内得满分，每增加 100 米扣减一定分数

3. **图片像素相似度**（权重 20%）
   - pHash/SSIM 整图像素级相似度
   - 作为辅助判断，排除明显非目标动物

4. **文本描述匹配**（权重 20%）
   - 品种、颜色、性别、特征的关键词重合度（BM25 或 Jaccard）
   - 辅助判断，尤其是 AI 向量相似度处于灰色地带时

> **注意**：原方案将"AI特征向量"与"鼻纹特征"分为两个独立维度，存在同一数据源重复计算问题。v1.6起统一为"AI鼻纹特征向量"，合并鼻纹区域专注提取+全局特征提取为一个维度。

检测结果：

├── 图片相似度：78%
├── 文本相似度：65%
└── 综合评分：高度疑似重复（92/100）

## 七、AI 技术方案（核心更新）

### 7.1 技术路线

```
数据准备 → 鼻部区域裁剪 → MobileNetV2 特征提取 → 128维向量存储 → 多维度融合匹配 → 应用输出
```

**核心选择**：MobileNetV2 迁移学习
- 使用 ImageNet 预训练的 MobileNetV2 骨干网络（轻量化，CPU 可推理）
- 在鼻纹数据集上微调
- 输出 128 维特征向量（权衡精度与存储/检索效率）

### 7.2 为什么选择迁移学习？

| 维度 | 从零训练 | 迁移学习（本案 MobileNetV2） |
|------|----------|------------------------------|
| 数据量 | 需要 ≥5000 组 | 2000 张足够 |
| 硬件要求 | 需要 GPU | CPU 可训练，i7+16GB 够用 |
| 训练时间 | 2-4 周 | 8-12 小时 |
| 准确率 | 从零起步 | 直接达到 85%+（目标 90%+） |
| 移动端推理 | 困难，模型过大 | 原生支持，INT8 量化后更小 |
| 维护 | 持续优化 | API 服务化，弹性扩展 |

### 7.3 模型训练方案

**两阶段训练流程（标准迁移学习做法）：**

**第一阶段（第 1-10 轮）—— 特征空间学习**
- 冻结 MobileNetV2 全部卷积层（ImageNet 预训练权重冻结不动）
- 仅训练新增的特征向量输出层（全连接层，输出 128 维）
- 学习率：0.001（较大，快速收敛新层）
- 早停条件：验证集准确率连续 5 次无提升

**第二阶段（第 11-30 轮）—— 细粒度微调**
- 解冻最后 2 个卷积块（block_12 / block_13），低学习率细调
- 学习率：0.0001（是第一阶段的 1/10，防止灾难性遗忘）
- 使用数据增强（翻转/旋转/亮度/小角度畸变）
- 目标：细化鼻纹细粒度特征，提升个体区分能力

> **备选训练策略**：若数据集规模有限（< 1000 组），可跳过第二阶段，仅用第一阶段 + 强数据增强也可达到 85%+ 准确率。

### 7.4 特征匹配算法

**相似度计算**：余弦相似度
```
相似度 = (向量A · 向量B) / (||A|| × ||B||)
范围：[0, 1]，越接近1越相似
```

**匹配阈值**：
```
相似度 ≥ 0.92：确认匹配（误认率 <0.1%）
0.82 ≤ 相似度 < 0.92：可疑匹配（需人工审核）
相似度 < 0.82：无匹配（判定为新动物）
```

### 7.5 多维度融合策略

```python
def calculate_duplicate_score(features: dict, db_entry: dict) -> float:
    """
    多维度综合评分（v1.6统一为4维度）
    权重分配：向量40% + 位置20% + 图片20% + 文本20%
    """
    # 维度1：AI鼻纹特征向量（核心，余弦相似度）
    nose_vec_sim = cosine_similarity(features.nose_vector, db_entry.nose_vector)

    # 维度2：GPS位置重合度（500m内满分，每增加100m扣分）
    distance_m = haversine(features.location, db_entry.location)
    location_score = max(0, 1 - (distance_m - 500) / 1000)  # 500m内=1, 1500m外=0

    # 维度3：图片像素相似度（pHash或SSIM）
    image_sim = phash_similarity(features.image_hash, db_entry.image_hash)

    # 维度4：文本描述关键词重合度（品种/颜色/性别/特征）
    text_sim = jaccard_similarity(features.keywords, db_entry.keywords)

    # 加权融合
    total_score = (
        0.40 * nose_vec_sim +    # AI鼻纹向量（核心）
        0.20 * location_score +  # 位置重合
        0.20 * image_sim +       # 图片相似
        0.20 * text_sim          # 文本匹配
    )

    return total_score  # 0-1，越高越可能是重复

def decide_duplicate(total_score: float) -> str:
    """根据综合评分输出判定结果"""
    if total_score >= 0.88:
        return "确认重复（自动合并建议）"
    elif total_score >= 0.75:
        return "疑似重复（需人工审核）"
    else:
        return "无匹配（判定为新动物）"
```

**阈值确定方法（需在 W3 实测后校准）：**
- 初定 0.88（确认重复）/ 0.75（疑似）作为基准
- W3 用验证集（200组正样本+200组负样本）跑 ROC 曲线
- 取 Youden's J Index 最优值作为最终阈值，不拍脑袋决定

### 重复判定定义（补充）

> **重复** = 同一只动物被不同用户多次发布救助留言
>
> **判定条件**：综合评分 ≥ 阈值（暂定 0.88，W3 实测后校准）
>
> **边界情况处理**：
> - 同城同品种短时间内（72小时内）高相似度 → 优先提示重复
> - 跨城同品种但定位距离 > 5km → 不判定为重复（可能是不同动物）
> - AI 向量相似度 ≥ 0.92 但其他维度全为0 → 直接判定重复（鼻纹置信度高）

3. **迁移学习应用**：用开源数据集 + 少量自采数据达到 90%+ 准确率

## 十三、风险与备选方案

### 风险 1：模型训练效果不确定

**可能情况**：数据集质量不足 / 训练收敛慢或过拟合 / CPU 推理速度慢

**备选方案**：
1. **简化模型**：使用 MobileNetV2 block_12 解冻策略替代全解冻，减少过拟合风险
2. **增强数据**：重点采集实际救助场景数据 + 强数据增强（1张→12张）
3. **降级方案**：如果模型效果不佳，可先用图片 pHash 相似度 + 定位作为主要判断，AI 向量作为辅助
4. **降低阈值**：若精度不够，把确认重复阈值从 0.88 降到 0.82（增加召回率牺牲精确率）

**建议**：W2-W3 优先验证模型效果，确认验证集 Accuracy > 80% 后再深入集成。

### 风险 2：数据集标注耗时超预期

**可能情况**：边采集边标注流程不顺畅，人工标注成为瓶颈

**备选方案**：招募 1-2 名同学协助标注，标注工具用 Python 脚本辅助（opencv 框选鼻部区域）

## 十四、图片采集规范

> AI 识别准确率 50% 取决于图片质量。以下为产品层规则，非技术实现细节。

### 基本要求

| 项目     | 规格                             |
| ------ | ------------------------------ |
| 单张大小   | ≥ 200KB，≤ 20MB                 |
| 分辨率    | 宽度 ≥ 640px，高度 ≥ 480px          |
| 鼻部区域占比 | 图片中鼻部不得小于整图 1/4                |
| 最少上传数量 | 每条留言至少 2 张不同角度照片（正面鼻纹 + 侧面/全身） |
| 支持格式   | JPG / JPEG / PNG               |

### 不合格图片处理

- 上传后系统自动检测图片质量（分辨率 / 清晰度 / 鼻部区域占比）
- 检测不合格：弹出提示"鼻部区域不够清晰，请重拍"，不提交
- 检测合格：提示"图片合格"，进入后续 AI 特征提取流程

### 采集引导

- 前端展示正确示范图 vs 错误示范图（过曝 / 模糊 / 鼻部被遮挡）
- 引导用户：保证光线充足、鼻部正对镜头、避免逆光

## 十五、恶意行为与风控规则

> 以下为业务层规则，定义系统需拦截的异常行为，不涉及技术实现细节。

### 用户行为规范

| 规则 | 触发条件 | 系统行为 |
|------|---------|---------|
| 发布频率限制 | 同一用户 5 分钟内发布超过 3 条 | 第 4 条开始限流，弹出验证码 |
| 同一设备 24 小时限制 | 同一设备 24 小时内发布超过 5 条 | 需人机验证，验证通过后可发布 |
| 图片去重 | 用户上传的照片哈希值与库中已有相同 | 拒绝发布，提示"该照片已在系统中存在" |
| 必填文字描述 | 留言文字描述为空 | 拒绝发布，提示"请填写动物描述" |

### 内容审核规则

| 审核对象 | 审核方式 | 违规处理 |
|---------|---------|---------|
| 图片 | 调用第三方图片审核 API（腾讯云/阿里云） | 不通过：拒绝发布，提示"图片不符合要求" |
| 图片审核接口超时/失败 | 降级为本地敏感词预检，图片先存草稿 | 草稿状态，审核通过后再发布 |
| 文字描述 | 本地敏感词库 + 第三方文本审核 | 不通过：拒绝发布，提示"描述包含敏感词" |

> 注：审核 API 选型、接入方式、备用方案详见技术方案文档。

### 违规处理机制

| 违规次数 | 处理方式 |
|---------|---------|
| 首次 | 管理员人工警告 |
| 二次 | 禁止发布 7 天 |
| 三次 | 账号封禁，IP 列入黑名单 |

### 举报机制

- 任意用户可举报他人的留言（选择举报原因：虚假信息 / 侵犯隐私 / 恶意骚扰 / 其他）
- 被举报留言对其他用户临时隐藏，等待管理员审核
- 管理员审核结果：举报成立 → 删除留言；举报不成立 → 恢复展示

## 十六、数据所有权与删除规则

### 用户数据权利

- 用户可自主删除自己的留言（删除后图片和位置数据不可恢复）
- 删除后：动物鼻纹特征向量是否保留用于匿名化统计
  → **保留**（脱敏后不关联个人身份，仅用于模型改进和统计）
- 管理员删除留言：需填写删除原因（信息虚假 / 侵犯隐私 / 其他），操作记录留存审计

### 数据保留策略

| 数据类型 | 保留时长 | 说明 |
|---------|---------|------|
| 留言图片（未认领） | 永久 | 用户删除后不可恢复 |
| 留言图片（已归档） | 2 年后转归档存储 | 降低存储费用 |
| 鼻纹特征向量 | 永久 | 脱敏后保留，用于 AI 模型改进 |
| 操作审计日志 | 1 年 | 满足监管要求 |
| 已归档动物记录 | 永久 | 品种/时间等统计数据，不可关联个人 |

### GPS 定位隐私

- 用户精确坐标不对外公开，展示时模糊至 500m 范围半径
- 用户可设置留言为"位置不可见"（管理员可见，救助者不可见）
- 动物保护协会角色可见统计数据，不可见精确位置

## 十七、AI 比对结果的展示与交互规则

### 用户发布时即时反馈

| 综合评分 | 系统行为 | 展示内容 |
|---------|---------|---------|
| ≥ 0.88（确认重复） | 弹窗警告，禁止直接发布（用户可选择"确认是同只动物，关联"或"仍要发布"） | 匹配项的照片 + 定位 + 相似度明细 |
| 0.75–0.88（疑似） | 弹窗提示，用户可选择"关联"或"忽略并发布" | 展示 Top-3 疑似匹配项 |
| < 0.75（无匹配） | 正常发布流程 | 无特殊提示 |

### AI 置信度可视化

- 用户可在"我的留言"中查看 AI 分析结果
  → "鼻纹清晰度：92%（优秀）/ 68%（一般，建议重拍）"
  → "与库中已有鼻纹的匹配情况：暂无匹配 / 发现 1 个疑似匹配"
  → 帮助用户理解 AI 工作原理，增加产品信任度

### Top-N 接近时的处理

场景：Top-1 与 Top-2 分数接近（0.91 vs 0.89）
→ 返回 Top-3 全部展示
→ 提示"有多个疑似匹配，请人工确认"
→ 不做自动判定，交给用户选择

## 十八、边界情况清单（Corner Cases）

| 场景 | 系统行为 |
|------|---------|
| 用户上传狗的照片，但文字描述写"猫" | AI 向量识别为狗，权重更高；提示"检测到您上传的是狗，请确认品种" |
| 同一用户发布多条几乎相同留言（疑似刷屏） | 触发频率限制，第 3 条起要求图形验证码 |
| 动物走丢 1 个月后找回，用户忘记关闭留言 | 90 天超时自动改为"超时未匹配"，用户可选择重发或关闭 |
| AI Top-1 与 Top-2 分数接近（0.91 vs 0.89） | 返回 Top-3，全部展示，人工确认 |
| 图片审核 API 免费额度用完 | 切换备用 API（预接入 2 家），API Key 存于配置，切换不涉及代码修改 |
| 多用户同时声称对同一只动物的所有权 | 先到先得；后到者标记"冲突，人工审核"，管理员介入 |
| 留言 GPS 定位明显异常（如跨省） | 提示"定位异常，请检查位置权限"，拒绝发布 |
| 管理员删除留言后，原主人希望恢复 | 不支持恢复；提示"请重新发布" |
